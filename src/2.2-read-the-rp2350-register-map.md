# 2.2 — Read the RP2350 register map

A GPIO output is controlled by several registers. This page derives the registers needed to drive our LED and the order in which to configure them. In [2.3](2.3-replace-gpio-calls-with-register-accesses.md), we will use that map in a complete program.

Complete [the SDK LED baseline](2.1-wire-and-verify-an-external-led.md) first. Keep its circuit: **non-wireless Pico 2 GP16, physical pin 21 → 1 kΩ resistor → LED anode; LED cathode → GND, physical pin 23**. Leave the button, Pi and probe detached. No wiring, flashing or live register writes are needed here; Pico USB can remain unplugged. The [Pico 2 pinout](https://datasheets.raspberrypi.com/pico/pico-2-datasheet.pdf#page=5) connects the board's physical numbering to GPIO names.

## An address selects hardware

A processor load or store presents an address to the chip's interconnect. The address determines which memory or peripheral receives the transaction. Ordinary variables commonly live in SRAM, whose main RP2350 address region starts at `0x20000000`. Peripheral registers occupy other regions. A store there is **memory-mapped I/O (MMIO)**: it controls hardware rather than storing an ordinary program object. These are addresses in the Pico's processor address map; they are not pointers usable by a Mac process. See the [RP2350 address map, §2.2](https://datasheets.raspberrypi.com/rp2350/rp2350-datasheet.pdf#page=28).

Keep these quantities separate:

| Quantity | Our example | Meaning |
| --- | --- | --- |
| Physical pin | 21 | Position on the Pico header. |
| GPIO number | 16 | The chip signal routed to that header pin. |
| Register address | `0xd0000018` | Where a store requests a GPIO output bit-set. |
| Bit mask | `1u << 16`, or `0x00010000` | Which GPIO the store affects. |
| Register value | For example, `GPIO_OUT` containing `0x00010000` | The output latch has GP16 high and its other bits low. |

Writing the integer `16` does not select GP16 in a bitmap register: binary `16` sets bit 4. Writing `0x00010000` to the right register selects bit 16. The meaning of that value depends on the destination register.

## Follow the output route

Three blocks cooperate:

- **SIO (Single-cycle I/O)** holds software-controlled output values and output enables.
- **IO_BANK0** selects which peripheral's output and enable reach each GPIO. Its multiplexer can connect SIO, UART, SPI and other functions.
- **PADS_BANK0** configures the electrical pad: the circuitry at the chip connection, including isolation, output disable, pulls, drive strength and slew rate.

For our output, the path is SIO output latch → IO_BANK0 function selection → pad output driver → GP16 → resistor and LED. SIO output enable and the pad's controls must also permit driving. Changing the output latch alone does not establish that entire route. The [RP2350 GPIO chapter](https://datasheets.raspberrypi.com/rp2350/rp2350-datasheet.pdf#page=540) describes these separate controls.

### Derive addresses from base and offset

The address map gives `IO_BANK0_BASE = 0x40028000`, `PADS_BANK0_BASE = 0x40038000`, and Secure `SIO_BASE = 0xd0000000`. We use the book's `rp2350-arm-s` firmware and SDK startup; this is not a Non-secure firmware configuration.

Each pad entry occupies four bytes. GPIO0 starts at pad offset `0x04`, after the bank's voltage-select register. Thus GPIO16 is at `0x04 + 16 × 4 = 0x44`. Each IO_BANK0 GPIO has a four-byte status register followed by a four-byte control register. GPIO16 control is at `0x04 + 16 × 8 = 0x84`.

The following are **32-bit registers**, accessed with aligned 32-bit operations. Offsets are bytes, not array indices. `RW` means readable and writable; `WO` means write-only. The reset column is the documented hardware reset state, not a promise about the state after boot ROM, SDK startup or earlier firmware has run.

| Block and register | Offset | Address | Access | Documented reset |
| --- | --- | --- | --- | --- |
| PADS_BANK0 `GPIO16` | `0x044` | `0x40038044` | RW fields | `0x00000116` |
| IO_BANK0 `GPIO16_CTRL` | `0x084` | `0x40028084` | RW fields | `0x0000001f` |
| SIO `GPIO_OUT` | `0x010` | `0xd0000010` | RW | `0x00000000` |
| SIO `GPIO_OUT_SET` | `0x018` | `0xd0000018` | WO | `0x00000000` |
| SIO `GPIO_OUT_CLR` | `0x020` | `0xd0000020` | WO | `0x00000000` |
| SIO `GPIO_OE` | `0x030` | `0xd0000030` | RW | `0x00000000` |
| SIO `GPIO_OE_SET` | `0x038` | `0xd0000038` | WO | `0x00000000` |
| SIO `GPIO_OE_CLR` | `0x040` | `0xd0000040` | WO | `0x00000000` |

These values come from the RP2350 datasheet's [SIO tables](https://datasheets.raspberrypi.com/rp2350/rp2350-datasheet.pdf#page=58), [GPIO16 control table](https://datasheets.raspberrypi.com/rp2350/rp2350-datasheet.pdf#page=575) and [GPIO16 pad table](https://datasheets.raspberrypi.com/rp2350/rp2350-datasheet.pdf#page=714). They also match SDK 2.3.1's `hardware/regs/addressmap.h`, `pads_bank0.h`, `io_bank0.h` and `sio.h` under `src/rp2350/hardware_regs/include/`. Use RP2350 headers: an RP2040 register table is not a substitute.

### Read fields before choosing a value

`GPIO16_CTRL.FUNCSEL`, bits 4:0 with mask `0x0000001f`, selects the function. Value `5` selects `sio_16`; reset value `31` selects NULL. Writing control value `0x00000005` also leaves the input, output, output-enable and interrupt overrides at their normal value, zero. Overrides can force or invert signals independently of the selected peripheral.

The pad register's implemented mask is `0x000001ff`; bits 31:9 are reserved. All listed pad fields are RW:

| Field | Mask | Reset | Our output setting |
| --- | --- | --- | --- |
| `ISO`, bit 8 | `0x100` | 1 | 0: remove pad isolation. |
| `OD`, bit 7 | `0x080` | 0 | 0: allow output; 1 overrides peripheral output enable. |
| `IE`, bit 6 | `0x040` | 0 | 0: input receiver unnecessary for this output. |
| `DRIVE`, bits 5:4 | `0x030` | 1 | 0: select 2 mA drive strength. |
| `PUE`, bit 3 | `0x008` | 0 | 0: no internal pull-up. |
| `PDE`, bit 2 | `0x004` | 1 | 0: no internal pull-down. |
| `SCHMITT`, bit 1 | `0x002` | 1 | 1: retain input hysteresis setting. |
| `SLEWFAST`, bit 0 | `0x001` | 0 | 0: slow slew. |

The resulting pad value is `0x00000002`. Schmitt hysteresis affects input reception; with `IE=0` we do not use it. Drive strength selects an electrical driver characteristic, not a constant-current source: the external 1 kΩ resistor still limits LED current. Slow slew is appropriate for this slowly blinking output. Crucially, **RP2350 pad isolation resets enabled** and must be removed for the configured pad to operate. These settings follow the [pad field descriptions](https://datasheets.raspberrypi.com/rp2350/rp2350-datasheet.pdf#page=714).

## Configure before enabling output

The actual `examples/pico/blink_registers.cpp` uses this sequence:

1. Write `0x00010000` to `GPIO_OE_CLR`. Disable SIO's GP16 output while configuring it.
2. Write that mask to `GPIO_OUT_CLR`. Select an initial low output latch while the driver is disabled.
3. Write `5` to `GPIO16_CTRL`. Route SIO to GP16 with normal overrides.
4. Write `2` to the GP16 pad register. Apply the pad settings above, including clearing isolation and output disable, while SIO output remains disabled.
5. Write the mask to `GPIO_OE_SET`. Enable the driver with its initial low value already selected.

This order avoids enabling our SIO output with an unwanted old latch value. It assumes the lesson's single owner and SDK baseline, not an arbitrary peripheral already driving GP16. Subsequent stores to `GPIO_OUT_SET` and `GPIO_OUT_CLR` turn this active-high LED on and off. Reading `GPIO_OUT` reports the output latch, not a measurement of the physical voltage or confirmation that the LED circuit works.

## A write can mean an operation

For `GPIO_OUT`, writing a value replaces the whole 32-bit latch. For `GPIO_OUT_SET`, each written 1 sets the corresponding latch bit; a written 0 leaves that bit alone. `GPIO_OUT_CLR` clears bits where the mask contains 1. Its reset-table entry does not make it a second readable output latch. Read the ordinary `GPIO_OUT` register to inspect state.

A software read-modify-write such as “read `GPIO_OUT`, OR in GP16, write back” has a gap between the read and write. An interrupt handler could change another GPIO in that gap; the stale write would undo its change. A single SET or CLR store lets the hardware modify only the selected bits. This prevents that lost-update pattern; it does not make conflicting decisions about the same pin correct.

The datasheet also defines generic peripheral atomic aliases at base-register address offsets `+0x1000` (XOR), `+0x2000` (SET), and `+0x3000` (CLR). **SIO is an exception:** use its dedicated registers in our table, not those generic offsets. See [§2.1.3, atomic register access](https://datasheets.raspberrypi.com/rp2350/rp2350-datasheet.pdf#page=24). Do not try to update part of a register with a byte store: the usual RP2350 narrow-write behaviour replicates data across the 32-bit write bus (§2.1.5).

Another access class is **write-one-to-clear (W1C)**. For example, IO_BANK0 raw interrupt edge flags are marked `WC` in the SDK: writing 1 acknowledges an event; writing 0 leaves it pending. A read-modify-write can accidentally acknowledge other events that were read as 1. This is different from clearing an ordinary RW control field, and different in purpose from SIO's output CLR operation. Always inspect access semantics per field; one register can mix access types. The [SDK's IO_BANK0 definitions](https://github.com/raspberrypi/pico-sdk/blob/2.3.1/src/rp2350/hardware_regs/include/hardware/regs/io_bank0.h) identify edge flags as `WC` and level flags as `RO`. We will use them in Chapter 4.

## Locate the definitions yourself

**Mac — working directory `~/hardware-from-software`.** Use your Chapter 1 checkout location if different. With its dependencies already installed, inspect the RP2350 definitions without requiring `rg`:

```sh
cd ~/hardware-from-software
python3 - <<'PY'
from pathlib import Path
base = Path('.deps/pico-sdk/src/rp2350/hardware_regs/include/hardware/regs')
names = {
    'addressmap.h': ('IO_BANK0_BASE', 'PADS_BANK0_BASE', 'SIO_BASE'),
    'pads_bank0.h': ('PADS_BANK0_GPIO16_OFFSET', 'PADS_BANK0_GPIO16_RESET'),
    'io_bank0.h': ('IO_BANK0_GPIO16_CTRL_OFFSET', 'IO_BANK0_GPIO16_CTRL_RESET'),
    'sio.h': ('SIO_GPIO_OUT_SET_OFFSET', 'SIO_GPIO_OE_CLR_OFFSET'),
}
for filename, symbols in names.items():
    print(filename)
    for line in (base / filename).read_text().splitlines():
        if line.startswith('#define ') and line.split()[1] in symbols:
            print(line)
PY
```

The definitions should agree with the table. The parallel `src/rp2350/hardware_structs/include/hardware/structs/` headers map these offsets to fields: `pads_bank0_hw->io[16]`, `io_bank0_hw->io[16].ctrl`, and SIO's `gpio_set`, `gpio_clr`, `gpio_oe_set`, `gpio_oe_clr`. These structs describe MMIO layout; they do not allocate ordinary RAM objects. [SDK 2.3.1's struct headers](https://github.com/raspberrypi/pico-sdk/tree/2.3.1/src/rp2350/hardware_structs/include/hardware/structs) provide the declarations.

If files are missing, restore Chapter 1's dependencies with `python3 scripts/setup_deps.py`. If addresses differ, check the SDK version and that the path contains `rp2350`, not `rp2040`. Later, a high output latch with a dark LED directs attention to output enable, mux, pad isolation/output disable, then the physical circuit; the latch alone cannot distinguish these failures.

This page's result is a source-derived map, not a hardware measurement. Leave the LED circuit intact and USB unplugged.
