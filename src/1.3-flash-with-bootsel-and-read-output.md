# 1.3 — Flash with BOOTSEL and read output

This lesson transfers the heartbeat built in [1.2](1.2-understand-the-smallest-useful-project.md) to the Pico 2, then reads its identity and increasing counter on the Mac. A successful copy and readable application output are separate checks: the first exercises the boot loader; the second exercises your firmware.

Use the **non-wireless Pico 2**, a data-capable micro-USB cable, and the USB-C adapter or hub identified in [0.4](0.4-a-labelled-tour-of-the-debug-probe-and-cables.md), if your cable needs one. Start with the Pico unpowered. Keep the existing GP16 (physical pin 21) → 1 kΩ resistor → LED anode circuit, with the LED cathode connected to GND (physical pin 23). Add no button or other wires. Leave the Pi and Debug Probe disconnected. Heartbeat does not configure or blink either LED; light is not the success criterion here.

## Two USB identities

**BOOTSEL mode** runs a loader from read-only memory inside the RP2350. The Mac sees a small USB mass-storage volume named **RP2350**. Copying a suitable UF2 image to that volume programs external flash and restarts the board. This is a programming interface, not a removable disk holding your source project. The name **RPI-RP2** belongs to the older RP2040 Pico; do not use it as this lesson's destination. [Official first-binary procedure](https://www.raspberrypi.com/documentation/microcontrollers/c_sdk.html#your-first-binaries).

After restarting, this application presents a USB **CDC** serial interface instead. CDC is a USB device class through which a terminal can exchange a stream of bytes. The same cable supplies power, transfers the firmware, and carries later output, but the loader and application expose different interfaces at different times. No GPIO UART wire or Debug Probe is involved. [Official USB console explanation, Chapter 5](https://datasheets.raspberrypi.com/pico/getting-started-with-pico.pdf).

## 1. Check the image on the Mac

Use the project directory acquired from the [public example archive in 1.1](1.1-install-a-reproducible-macos-toolchain.md#2-put-the-example-tree-in-a-known-location). These commands assume `~/hardware-from-software`; substitute your actual project directory if you used another location.

**Mac — Terminal, working directory: `~/hardware-from-software`:**

```sh
cd ~/hardware-from-software
python3 scripts/setup_deps.py
python3 scripts/build_examples.py --pico
ls -l .build/pico/heartbeat.uf2 .build/pico/heartbeat.elf
```

The build script selects `pico2`, `rp2350-arm-s` and a Debug build. Copy the **UF2** below; retain the **ELF** for later debugging. Both files must exist and be nonempty. The recorded project checks compiled all twelve Pico targets; no connected-board execution was verified.

This is the complete application you are installing, from `examples/pico/heartbeat.cpp`:

```cpp
{{#include ../examples/pico/heartbeat.cpp}}
```

The shared CMake project enables USB stdio and disables UART stdio. `stdio_init_all()` initialises that USB backend. Each iteration prints the identity `hardware-from-software heartbeat v1` and a counter, then requests a one-second sleep. The text `v1` is our application identity, not the SDK version.

## 2. Enter BOOTSEL before applying power

With the Pico still disconnected, press and hold its **BOOTSEL** button, just below the USB connector. While holding it, connect the Pico's micro-USB port to the Mac using the data cable. Release the button after the **RP2350** volume appears.

Holding BOOTSEL before connection enters the loader without first running whatever firmware may already be in flash. Simply pressing BOOTSEL on an already running board is not this power-on procedure.

In **Mac Finder**, look under **Locations** for **RP2350**. If the sidebar hides external disks, use **Finder → Settings → Sidebar → External disks**. You can also inspect the mount directly:

**Mac — Terminal, working directory: `~/hardware-from-software`:**

```sh
ls /Volumes
ls /Volumes/RP2350
```

Continue only when that destination is present. A different volume name warrants checking the board identity and connected devices before copying anything.

## 3. Copy the UF2 and let the board restart

**Mac — Terminal, working directory: `~/hardware-from-software`, with RP2350 mounted:**

```sh
cp .build/pico/heartbeat.uf2 /Volumes/RP2350/
```

Alternatively, in Finder use **Go → Go to Folder…**, enter `~/hardware-from-software/.build/pico`, and drag `heartbeat.uf2` onto **RP2350** under **Locations**. Choose one transfer method.

The volume should disappear automatically when the transfer finishes and the Pico restarts. Leave the cable attached. There is no manual eject step during this transfer. Automatic ejection is documented by Raspberry Pi's [UF2 installation procedure](https://www.raspberrypi.com/documentation/microcontrollers/pico-series.html#debug-using-a-pico-series-device). Disappearance alone does not establish that the intended application is running; check its identity next.

## 4. Find and open the serial device

Wait briefly for macOS to discover the application's USB interface. This discovery is called **enumeration**. List matching devices:

**Mac — Terminal, working directory: `~/hardware-from-software`:**

```sh
find /dev -maxdepth 1 -name 'cu.usbmodem*' -print
```

Use the actual `/dev/cu.usbmodem…` path printed on your Mac. The suffix can change after reconnection; do not copy a suffix from a screenshot. If several devices match, close any serial terminal, note the list, unplug this Pico, list again, and reconnect it normally without BOOTSEL. The path that disappears and returns identifies this board. Recheck after every restart.

Open it with macOS's `screen`. In the command below, replace the entire placeholder path with the one you found:

**Mac — Terminal, working directory: `~/hardware-from-software`:**

```sh
screen /dev/cu.usbmodemYOUR_SUFFIX 115200
```

`115200` supplies a conventional serial line-coding setting to the terminal. Here the bytes travel as USB packets; that number does not configure a physical 115200-bit/s UART on GP0/GP1. The [SDK's USB stdio implementation](https://github.com/raspberrypi/pico-sdk/blob/2.3.1/src/rp2_common/pico_stdio_usb/stdio_usb.c) writes through TinyUSB's CDC interface.

Expected output is **illustrative, not a recorded hardware trace**:

```text
hardware-from-software heartbeat v1: 8
hardware-from-software heartbeat v1: 9
hardware-from-software heartbeat v1: 10
```

The first visible count need not be zero. This firmware starts counting before you open the terminal, and the default SDK connection-wait timeout is zero. Text produced without a connection can be discarded; it is not a replayable log. [SDK 2.3.1 USB stdio configuration](https://github.com/raspberrypi/pico-sdk/blob/2.3.1/src/rp2_common/pico_stdio_usb/include/pico/stdio_usb.h).

Several successive lines with the expected identity and increasing count establish the reader's runtime check. Approximate one-second spacing is expected from the loop, but this is not a timing measurement. Closing the terminal does not stop the Pico.

To exit `screen`, press **Ctrl+A**, release both keys, then press **Ctrl+\\**, and answer **Y** if asked to confirm. This terminates the session and releases the port. Ctrl+A followed by D only detaches it, leaving a process that can still own the device. The installed **Mac** command `man screen` documents the quit binding.

## Diagnose the observed symptom

**No RP2350 volume appears.** Disconnect and repeat the hold-before-power sequence. Try a known data-capable cable: a charge-only cable can supply power without USB data. Check both ends, the adapter and the hub; simplify the connection or try another Mac port. A power LED or warm board would not establish a data path. If macOS asks whether to allow the USB accessory, allow the Pico connection.

**The copy fails or RP2350 stays mounted.** Check that the source is this build's `heartbeat.uf2` and the destination is the actual mounted volume. A disconnect error alone is ambiguous: automatic removal is expected, but a failed transfer may also lose the connection. Re-enter BOOTSEL, retry with the verified cable, then check serial identity. Do not judge success from a filesystem message alone.

**The volume disappeared but no serial device appears.** Ensure BOOTSEL is released and reconnect normally. Rebuild and reflash the heartbeat if you may have copied another image. Application USB requires working firmware; the loader's mass-storage interface does not prove its USB stdio is enabled.

**The port exists but `screen` is blank or reports it is busy.** Quit other terminal applications and any detached `screen` session; `screen -ls` lists sessions. Recheck the device path after reconnection, open it again, and wait for several heartbeat iterations. This program does not respond to typed commands. Garbled or unrelated text warrants checking that you opened the Pico rather than another USB device.

**Unknown or broken firmware runs after reconnection.** Disconnect, hold BOOTSEL, reconnect, and copy the known heartbeat again. The [ROM-resident loader](https://www.raspberrypi.com/documentation/microcontrollers/pico-series.html#reset-flash-memory) remains available independently of application USB code. Recovery does not require erasing all flash or attaching a debugger.

## Leave a known state

Quit the serial session, then unplug the Pico before touching its breadboard wiring. Keep the LED circuit assembled, the Pi and probe disconnected, and both build artifacts. The next lesson, [1.4 — Make the build–flash–observe loop repeatable](1.4-make-the-build-flash-observe-loop-repeatable.md), makes a deliberate source change and verifies the new identity through this same path.
